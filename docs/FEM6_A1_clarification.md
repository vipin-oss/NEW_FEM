## 2. Why the delivered window is correct

The scheme is explicit with a *lagged* right-hand side: when `q(:,n+1)` is
formed, every term is evaluated at time level `t_{n-1}` (the array index `n`
holds `q^{n-1}`). The Caputo derivative must therefore also be evaluated at
`t_{n-1}`, not at `t_n`:

```
D^α q(t_{n-1}) = dt^{-α}/Γ(2-α) Σ_{k=0}^{n-2} b_k (q^{n-1-k} − q^{n-2-k})
               = dt^{-α}/Γ(2-α) Σ_{k=0}^{n-2} b_k Δq_{n-2-k}
```

With `dq(:,m) = Δq_{m-1}`, the delivered line

```
Dq = c * Σ_{j=1}^{n-1} dq(:,n-j) b(j)
   = c * Σ_{j=1}^{n-1} Δq_{n-j-1} b_{j-1}      [j = k+1]
   = c * Σ_{k=0}^{n-2} b_k Δq_{n-2-k}
```

is **exactly** the formula above. Both indices shift together, which is why the
window looks "one short" if you compare it with the formula written at `t_n`
instead of `t_{n-1}`.

The `α ≥ 1` branch (`b = [1 0 …]`, `c = 1/dt`) then gives `Dq = Δq_{n-2}/dt`,
i.e. the backward-difference velocity at the lagged level — consistent with the
rest of the stencil.

## 3. Where my error came from

My check script (`l1_offbyone`, since deleted) transcribed the line as

```python
Dq_old = c * np.dot(dq[n-1:0:-1], b[1:n])     # WRONG
```

while the MATLAB is

```python
Dq = c * np.dot(dq[n-2::-1], b[0:n-1])        # what the .m actually does
```

I shifted **both** slices by one, which pairs `b₁` with an increment two steps
old and, at `α = 1`, makes `b[1:] = 0` so the damping term becomes identically
zero. The "32× larger late-time oscillation" I reported was a property of *my
mis-transcription*, not of your code. I compared my broken variant against my
own working one and attributed the difference to the manuscript code. That is
exactly the failure mode your rule "every code claim must be verified by
running the code, not by re-running the same script" is designed to catch, and
I should have transcribed from the file line by line the first time.

## 5. The stability warning is also fine (B2 downgraded)

I had called the `(w dt)² > 2 || γ > 1.5` check "heuristic". I scanned the
actual stability boundary of the delivered stencil (constant force, 4000 steps,
blow-up = `|q| > 10² q_static`):

| `w·dt` | γ = 0.5 | 1.0 | 1.4 | 1.6 | 2.0 |
|---|---|---|---|---|---|
| 0.05 | ok | ok | ok | ok | ok |
| 0.10 | ok | ok | ok | ok | **blow-up** |
| 0.20 | ok | ok | ok | ok | **blow-up** |
| 1.00 | ok | ok | ok | **blow-up** | **blow-up** |

The true boundary is γ ≈ 1.5–2.0 and depends weakly on `w·dt`; your threshold
γ > 1.5 is conservative (it warns slightly before the scheme dies) and the
`(w dt)² > 2` part is the classical central-difference limit. **Keep it.** The
only remark worth adding to the paper is that the bound is empirical, not
derived.
